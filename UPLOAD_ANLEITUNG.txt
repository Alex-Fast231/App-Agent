FaSt-Doku – Vollständiger App-Stand für ein neues GitHub-Repo
================================================================
Stand: 2026-08-19, fünfte Session (Feldkoordinaten-Fix + Fax/PDF-Upload), Version 3.9.18

Diese ZIP enthält den KOMPLETTEN, lauffähigen und getesteten Stand der
App (alle 47 Dateien, inkl. neuem Fax/PDF-Upload für digital empfangene
Rezepte), direkt aus der getesteten Arbeitsumgebung exportiert. Kein
Zusammenfügen mit älteren ZIPs nötig – einfach diese verwenden.

So laden Sie ein neues GitHub-Repo hoch
------------------------------------------
Option A – über die GitHub-Weboberfläche (am einfachsten):
1. Auf github.com ein neues, leeres Repository anlegen (KEIN README,
   .gitignore oder Lizenz beim Anlegen auswählen).
2. Im neuen Repo auf "uploading an existing file" klicken.
3. Alle Dateien/Ordner aus dieser ZIP (entpackt) per Drag & Drop
   hochladen. Achtung: der versteckte Ordner ".githooks" wird von
   manchen Datei-Explorern nicht angezeigt – ggf. "versteckte Dateien
   anzeigen" aktivieren (nicht zwingend nötig für den Betrieb der App
   selbst, nur für die automatische Versionsnummer-Erhöhung bei
   künftigen lokalen Commits relevant).
4. Commit direkt im Browser bestätigen.

Option B – über die Kommandozeile (falls git installiert ist):
    cd <entpackter-ordner-dieser-zip>
    git init
    git add -A
    git commit -m "Initial commit"
    git branch -M main
    git remote add origin https://github.com/<IHR-NUTZERNAME>/<REPO-NAME>.git
    git push -u origin main

Nach dem Hochladen (nur bei Option B relevant, für zukünftige lokale
Weiterentwicklung mit automatischer Versionserhöhung):
    git config core.hooksPath .githooks

Wenn Sie stattdessen ein BESTEHENDES Repo aktualisieren möchten:
einfach alle Dateien aus dieser ZIP über die bestehenden Dateien im
Repo kopieren/hochladen (überschreiben) und committen.

Neu in dieser Version (gegenüber der letzten ZIP)
----------------------------------------------------
1. Neuer Button "📠 Fax/PDF hochladen" bei "Patient + Rezept anlegen":
   Alternative zur Kamera-Aufnahme für Therapeuten, die Rezepte digital
   erhalten (z.B. per Fax als PDF, oder als Bilddatei). Die Datei wird
   ausschließlich lokal im Browser verarbeitet (PDF-Rendering per
   vendorierter PDF.js-Bibliothek) und nutzt danach dieselbe
   Muster-13-Feld-für-Feld-Texterkennung wie die Kamera-Aufnahme.
2. Bugfix am Ausrichtungsrahmen: Das Seitenverhältnis des gestrichelten
   Rahmens (Kamera-Vorschau UND jetzt auch Datei-Vorschau) war durch
   einen Formel-Fehler zu groß berechnet und ragte über den sichtbaren
   Bereich hinaus. Jetzt korrekt und für beide Ansichten identisch.

Details siehe HANDOFF_SUMMARY.md, Abschnitt "-1" (oben) - dort auch die
wichtige Bitte um einen echten Testlauf mit einem fotografierten ODER
hochgeladenen Muster-13-Formular, da sich die eigentliche
Texterkennung in der Entwicklungsumgebung nicht mit echten
Rezept-Dateien testen ließ (die Sprachdaten-CDN ist dort blockiert).
Das PDF-Rendering selbst wurde davon unabhängig vollständig getestet
und funktioniert nachweislich offline im Browser.

--------------------------
