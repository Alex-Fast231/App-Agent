FaSt App – Vollständiger App-Stand für ein GitHub-Repo
================================================================
Stand: 2026-08-22, siebte Session inkl. Nachtrag, Version 3.9.30

Diese ZIP enthält den KOMPLETTEN, lauffähigen und getesteten Stand der
App (alle Dateien außer dem separaten Viewer), direkt aus der
getesteten Arbeitsumgebung exportiert.

Der Viewer wird wie gewünscht separat als eigene Datei bereitgestellt
(FaSt-Viewer.zip) - diese ZIP hier ist ausschließlich die Haupt-App.

   sich direkt über einen eigenen "Drucken"-Button drucken/als PDF
   speichern - auch in der installierten App.

   dort selbst:
   - "Als Datei herunterladen" - lädt die PIN-geschützte (1550)

   - "Per E-Mail senden" - lädt die ZIP ebenfalls herunter UND öffnet
     das E-Mail-Programm mit vorbereitetem Betreff/Text an
     physio_fast@gmx.de. Die heruntergeladene Datei muss dabei manuell

   Im Dashboard gibt es dafür einen Bereich "Backup-Erinnerung" mit
   Status, Verlauf und einem Button "Jetzt Backup machen" für den
   Bedarfsfall.

So laden Sie ein neues GitHub-Repo hoch
------------------------------------------
Option A – über die GitHub-Weboberfläche (am einfachsten):
1. Auf github.com ein neues, leeres Repository anlegen (KEIN README,
   .gitignore oder Lizenz beim Anlegen auswählen).
2. Im neuen Repo auf "uploading an existing file" klicken.
3. Alle Dateien/Ordner aus dieser ZIP (entpackt) per Drag & Drop
   hochladen. Achtung: der versteckte Ordner ".githooks" wird von
   manchen Datei-Explorern nicht angezeigt – ggf. "versteckte Dateien
   anzeigen" aktivieren (nicht zwingend nötig für den Betrieb der App
   selbst, nur für die automatische Versionsnummer-Erhöhung bei
   künftigen lokalen Commits relevant).
4. Commit direkt im Browser bestätigen.

Option B – über die Kommandozeile (falls git installiert ist):
    cd <entpackter-ordner-dieser-zip>
    git init
    git add -A
    git commit -m "Initial commit"
    git branch -M main
    git remote add origin https://github.com/<IHR-NUTZERNAME>/<REPO-NAME>.git
    git push -u origin main

Nach dem Hochladen (nur bei Option B relevant, für zukünftige lokale
Weiterentwicklung mit automatischer Versionserhöhung):
    git config core.hooksPath .githooks

Wenn Sie stattdessen ein BESTEHENDES Repo aktualisieren möchten:
einfach alle Dateien aus dieser ZIP über die bestehenden Dateien im
Repo kopieren/hochladen (überschreiben) und committen. Achtung: die
Datei "modules/autoExport.js" existiert in dieser Version nicht mehr
(durch "modules/backupReminder.js" ersetzt) - falls sie in Ihrem
bestehenden Repo noch vorhanden ist, bitte manuell löschen.

Details siehe HANDOFF_SUMMARY.md, Abschnitt "7b".

Deployment (z.B. Netlify)
--------------------------
netlify.toml enthält eine explizite Regel, die /vorlagen/* von der
SPA-Weiterleitung ausnimmt (fürs Unterschriftenblatt-PDF).

Bei Fragen oder falls nach dem Hochladen etwas nicht funktioniert:
bitte mit genauer Fehlerbeschreibung/Screenshot zurückmelden.
