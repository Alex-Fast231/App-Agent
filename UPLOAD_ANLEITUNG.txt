FaSt-Doku – Vollständiger App-Stand für ein neues GitHub-Repo
================================================================
Stand: 2026-08-20, fünfte Session (Fax/PDF-Upload-Rückbau + tägliches
Viewer-Backup per E-Mail), Version 3.9.20

Diese ZIP enthält den KOMPLETTEN, lauffähigen und getesteten Stand der
App (alle 43 Dateien), direkt aus der getesteten Arbeitsumgebung
exportiert. Kein Zusammenfügen mit älteren ZIPs nötig – einfach diese
verwenden.

So laden Sie ein neues GitHub-Repo hoch
------------------------------------------
Option A – über die GitHub-Weboberfläche (am einfachsten):
1. Auf github.com ein neues, leeres Repository anlegen (KEIN README,
   .gitignore oder Lizenz beim Anlegen auswählen).
2. Im neuen Repo auf "uploading an existing file" klicken.
3. Alle Dateien/Ordner aus dieser ZIP (entpackt) per Drag & Drop
   hochladen. Achtung: der versteckte Ordner ".githooks" wird von
   manchen Datei-Explorern nicht angezeigt – ggf. "versteckte Dateien
   anzeigen" aktivieren (nicht zwingend nötig für den Betrieb der App
   selbst, nur für die automatische Versionsnummer-Erhöhung bei
   künftigen lokalen Commits relevant).
4. Commit direkt im Browser bestätigen.

Option B – über die Kommandozeile (falls git installiert ist):
    cd <entpackter-ordner-dieser-zip>
    git init
    git add -A
    git commit -m "Initial commit"
    git branch -M main
    git remote add origin https://github.com/<IHR-NUTZERNAME>/<REPO-NAME>.git
    git push -u origin main

Nach dem Hochladen (nur bei Option B relevant, für zukünftige lokale
Weiterentwicklung mit automatischer Versionserhöhung):
    git config core.hooksPath .githooks

Wenn Sie stattdessen ein BESTEHENDES Repo aktualisieren möchten:
einfach alle Dateien aus dieser ZIP über die bestehenden Dateien im
Repo kopieren/hochladen (überschreiben) und committen. Achtung: der
Ordner "vendor/pdfjs" existiert in dieser Version nicht mehr (siehe
unten) – falls er in Ihrem bestehenden Repo noch vorhanden ist, bitte
manuell löschen.

Neu in dieser Version (gegenüber der letzten ZIP)
----------------------------------------------------
1. Der "Fax/PDF hochladen"-Button wurde wieder ENTFERNT (Rückmeldung:
   empfangene Faxe sind oft verschoben/schlecht leserlich, kein echter
   Mehrwert). Die Kamera-Aufnahme bleibt unverändert die einzige
   Fotoerkennung. Der vendorierte PDF.js-Ordner wurde komplett entfernt.
2. NEU: Tägliches automatisches Backup für den separaten Offline-
   Viewer. Läuft im Hintergrund direkt nach jedem Entsperren der App
   (wenn seit dem letzten Versand mind. 1 Tag vergangen ist), ohne
   Rückfrage. Es wird eine ZIP-Datei mit einer einzigen JSON-Datei
   (alle App-Daten) per E-Mail an physio_fast@gmx.de geschickt. Die
   ZIP ist mit der PIN 1550 entsperrbar (auch im mitgelieferten
   viewer/index.html, das jetzt nach der PIN statt nach dem
   Praxispasswort fragt).

   WICHTIG - Sicherheitshinweis: Eine 4-stellige PIN ist deutlich
   schwächer als ein echtes Passwort. Falls die E-Mail abgefangen
   würde, ließe sich die ZIP mit vertretbarem Aufwand per Brute-Force
   öffnen. Das ist eine bewusste, von Ihnen gewünschte Abwägung
   zwischen einfacher Bedienbarkeit im Viewer und Schutzstärke.

   Das manuelle "Backup exportieren/importieren" in den Einstellungen
   (weiterhin mit dem echten Praxispasswort) ist davon nicht
   betroffen und funktioniert unverändert.

Details siehe HANDOFF_SUMMARY.md, Abschnitt "0" (oben) - dort auch der
Hinweis, dass die tatsächliche Zustellung der ersten Backup-E-Mail
noch nicht außerhalb der Entwicklungsumgebung bestätigt wurde (bitte
nach dem nächsten Entsperren der App im Postfach physio_fast@gmx.de
prüfen).
